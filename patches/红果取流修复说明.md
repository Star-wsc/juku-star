# 红果取流修复补丁（2026-10-16）

## 问题

红果播放报：

```text
播放地址解析失败：红果 App 取流失败…网页取流失败…备用取流失败…
```

原因：

1. 旧接口 `POST /novel/player/video_model/v1/` 现在返回 **空包**
2. 网页播放页改成 `protectedPlayback`，不再在 HTML 里给 `main_url`
3. 网页密钥 tag=`22` 时解包偏移方向与 App 相反（旧代码只处理了 App 方向）

## 修复内容（只动后端红果取流，不影响其它站源）

| 文件 | 改动 |
|------|------|
| `provider_hongguo_native_media.go` | 改用预加载接口 `multi_video_model/preload/v1/`，跳过 bytevc2，选 bytevc1/H.264 |
| `provider_hongguo_web_media.go` | 新增：`POST /api/video/protected/play-info`，支持 DASH 分离音视频 + CENC |
| `provider_hongguo.go` | 页面 `protectedPlayback` 或无 `main_url` 时走 play-info |
| `provider_hongguo_playback.go` | 密钥解包：tag `22`/`webdevice` 用 +delta，`11`/`appdevice` 用 -delta |
| `provider_media.go` | `providerMedia` 增加 `AudioURL` |
| `playback_stream.go` | FFmpeg 双输入（视频+音轨），CENC key 挂在每个 `-i` 前 |

## 取流顺序

1. **App 预加载口**（主路径，后面的集靠它）
2. 网页 `protected/play-info`（备用）
3. 第三方备用口 `djapi.999888456.xyz`

## 部署（Linux）

```bash
# 备份
cp juku-v2 juku-v2.bak-$(date +%Y%m%d)

# 若用 systemd，先停再替换（否则 Text file busy）
sudo systemctl stop juku.service
cp juku_linux_amd64_hongguo-fix /path/to/juku-v2
sudo systemctl start juku.service
```

源码合并：把 `src/` 里 6 个文件覆盖到工程的 `internal/app/` 后：

```bash
go build -o juku-linux-amd64 .
```

需要 Go 1.21+。数据目录、下载目录、端口参数不变。

## APP 要不要改？

**本次红果修复不需要改 Android/iOS 客户端。**

- 后端仍走原有 `/api/ui/playback/hls/open` 代理链路出流
- 客户端收到的还是服务端 m3u8/转码地址，和以前一样

可选（非必须）：

- 客户端若开启后端「优先原始 MP4 / HLS」直连，才需要客户端能播 **原始 mp4 / 原始 m3u8**（不要写死 `application/x-mpegURL`）
- 我们此前做过的 App `1.3.6` 就是这个兼容；**不升级 App 也能用本后端补丁看红果**
